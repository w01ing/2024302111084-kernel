# lab3 官方用户态测试集（课程组提供 · 评分参考）

> 版本：v2（2026-09-29，随 lab3 增量包 v2 修订：明确前置能力清单，含 sbrk 地址空间增长）。

构建方式：与 lab2 相同的内嵌构建方式，在 `UPROGS` 中追加 `badaccess memcap`
（将本目录两个 .c 拷贝到 `user/` 目录后即可纳入既有构建规则）。

**前置条件**（四项能力均已实现后才可运行，缺一将出现测试失败而非测试误报）：
1. SV39 三级页表与用户进程独立地址空间；
2. guard page（保护页）机制；
3. 物理内存配额管理（`LAB3_MEMCAP_DELTA`）；
4. **sbrk 系统调用（SYS_sbrk，地址空间动态增长）**——两项测试均依赖：
   badaccess 的 TEST-3b 先 `sbrk(4096)` 再越界访问；memcap 全程循环 `sbrk` 直至
   内存耗尽。sbrk 的实现要求见《能力目标与接口约定》§1.6。

| 测试程序 | 测试覆盖范围 | 判定合格标准 |
|---|---|---|
| `badaccess` | 越界访问或触碰保护页被安全终止 | TEST-3a 与 TEST-3b 均显示 PASS：触发异常的子进程被内核安全终止而非异常存活，父进程 wait 正确回收子进程，sh 保持正常运行 |
| `memcap` | 物理内存上限与 OOM 错误处理 | TEST-4 显示 PASS：sbrk 分配超出配额上限时返回错误（-1）而非导致内核崩溃，已成功分配的内存可正常读写 |

补充说明：
- 两项测试均针对**通用的系统不变式**进行验证——内存上限的具体数值因学生参数而异
  （`LAB3_MEMCAP_DELTA`），测试只验证"达到配额上限时返回错误、内核保持正常稳定"的基础规范行为；
- badaccess 的 TEST-3a（写地址 0 必须被杀）隐含要求**用户代码页不可写**（R+X 权限）——
  若用户镜像整体映射为可读可写可执行，该测试将失败。段级权限的实现要求见
  《能力目标与接口约定》§1.4；
- memcap 的完整运行需分配至内存上限（约 2 千余轮、每轮 64KB），在 QEMU 下需要数十秒，
  **耗时属正常现象，请勿在等待期间中断**；若等待超过五分钟无输出，优先检查分配器的
  回收路径复杂度（顺序空闲链表的逐页有序插入在万页规模下不可用，参见说明书阶段一的
  数据结构讨论）。
