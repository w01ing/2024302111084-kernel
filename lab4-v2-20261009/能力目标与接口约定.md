# lab4 · 能力目标与接口约定（进程调度：多任务并发与调度策略）

> **增量包版本**：v2（2026-10-09），由课程组统一发放。

> 本实验实现多任务上下文切换与进程调度策略：
  将 lab2 阶段简化的单任务返回升级为完整的多任务调度机制；lab2 中介绍的上下文切换 14 个寄存器保存逻辑
  将在本实验中正式投入使用（由预置汇编模块 swtch.S 提供底层支撑）。

## 1. 能力目标（由你设计并实现）

1. yield/sleep/wakeup 以及 scheduler 调度主循环等核心多任务管理机制（函数命名可自定）。
2. 实现个人定制的进程调度策略：依据 `LAB4_POLICY_ID`（0–9，详见后文分配表：
   包含多级反馈队列 MLFQ、彩票调度、步长调度、优先级调度等）。
3. sched() 调度切换过程中的锁持有不变式：调用切换时必须且恰好持有当前进程锁。
4. 消除丢失唤醒（Lost Wakeup）竞态：确保状态检查与进程休眠在同一临界区内原子化完成。
5. 课程测试依赖的系统调用：`pause(n)`（SYS_pause = 13，按 tick 休眠，用 sleep/wakeup 实现）、
   `schedstat`（23）、`time_rdtime`（24）、`setickets`（25）；`wait` 须写回子进程退出码。
   `kill`（6）为可选项，测试不强制依赖。本实验不要求实现 `pipe`。详见 `support/tests/README-tests.md`。

## 2. 接口约定与核心规范

1. **swtch 汇编 ABI 规范**：被调用者保存（callee-saved）的 14 个寄存器保存与恢复协议详见
   kernel/swtch.S 注释；被换入进程从哪条路径恢复运行，调度主循环必须与之精密契合。
2. **schedstat 观测格式规范**：以 `support/schedstat.patch` 所定义的补丁规范为准
   （既作为数据埋点接入参考，也是输出接口规范；调度统计的输出格式属于 ABI 规范，具体策略实现保持独立）。
3. **测试规范**：`support/tests/` 目录下的 bench（全部策略）、lottery_test（ID 3–5）、stride_test（ID 6–7）
   通过上述系统调用采样观测调度行为；ID 0–2、8–9 使用 schedstat 自行编写观测程序；
   `make qemu` 基础启动规范保持不变。适用表与判据见 `support/tests/README-tests.md`。
4. **功能回归测试规范**：lab3 实现的 dump_pagetable 必须仍可正常调用且输出正确。

## 3. 设计决策（设计笔记必须明确回答；现场验收重点考查）

- 策略元数据是扩展在 struct proc 中还是维护于独立调度表？学生可自主扩充 proc.h——数据结构的
  组织形式属于本实验明确考核内容。
- 就绪队列、时间片计数器与权重/票数的锁保护粒度，以及其与 scheduler 进程锁的关系。
- 调度时间片与 `LAB2_TICK` 的对应关系；抢占调度点的切入位置（如时钟中断返回路径）。
- 避免丢失唤醒的机制：状态检查与进入休眠如何置于同一互斥临界区内；kill 系统调用为何不能
  破坏处于 SLEEPING 状态但未满足唤醒条件的进程。

## 5. 里程碑自检

1. bench 通过：fork/exit/wait 往返与并发子进程回收均正常，无丢失唤醒（长时间并发运行不出现挂起或死锁）；
2. schedstat 采集的统计数据符合所选调度策略的理论分布比例（彩票调度的 CPU 占比约等于票数比、步长调度执行量符合配额）；
3. 触发调试观测命令（如 Ctrl-P 或自定义打印函数）时，进程状态机转换完整自洽；
4. **功能回归**：重新执行 lab3 的 dump_pagetable，地址空间结构验证正确。

## 7. 观测系统调用接口定义（本包 gifts/ 已定稿）

`int schedstat(int pid, int *cpu_ticks, int *last_slice_ticks)` —— 系统调用号
**SYS_schedstat = 23**（`pid = -1` 表示自身）；时间戳观测 `unsigned long time_rdtime(void)` —— 系统调用号 **SYS_time_rdtime = 24**（返回 `time` CSR 计数，非 tick）；票数设置 `int setickets(int tickets)` —— 系统调用号 **SYS_setickets = 25**（设定值覆盖策略默认票数；非彩票/步长策略可只记录、仍返回 0）。（kernel/syscall.h、user.h 与 usys.pl 均已在增量包中完成更新，请以包内版本为准）；详细语义见 `support/schedstat.patch` 头部注释。测试程序通过此类接口进行调度行为采样与验证。

## 8. LAB4_POLICY_ID 调度策略分配表（参考方案）

`LAB4_POLICY_ID = sid % 10`，票数/配额参数统一由 `7 + sid % 13` 计算派生（与 lab1 的参数派生规则保持一致）：

| ID | 策略族 | 变体分支 | 可观测特征（自动化测试与现场评分依据） |
|:--:|---|---|---|
| 0 | MLFQ | 2 级队列，高优先级时间片 = LAB2_TICK，低优先级 ×2 | schedstat last_slice 呈现两档分布 |
| 1 | MLFQ | 3 级队列，时间片逐级 ×2 | 呈现三档时间片分布 |
| 2 | MLFQ | 4 级队列，时间片逐级 ×2 | 呈现四档时间片分布 |
| 3 | 彩票 | 静态票数 = 7 + sid % 13 | 较长观察窗口内 CPU 占比与票数比近似相等 |
| 4 | 彩票 | 动态：每主动让出 1 次 +1 票，上限 32 | 短窗口占比随运行时间动态收敛 |
| 5 | 彩票 | 比例共享：按进程名称分配票数 hi=1 / spin=2 / sh=4 | CPU 占用比例近似呈现 1:2:4 |
| 6 | 步长 | stride = 1000 / tickets，tickets = 7 + sid % 13 | stride_ratio 近似等于票数比且调度分配均匀 |
| 7 | 步长 | 比例票数同 ID 5 的分配规则 | 同上（比例呈 1:2:4） |
| 8 | 优先级 | 4 级静态优先级，数值较大者优先运行 | 高优先级独占运行期与低优先级等待边界明确可测 |
| 9 | 优先级 | 2 级优先级 + 老化机制：每等待 8 个 tick 提升 1 级 | 低优先级进程最终获得 CPU 调度执行（无饥饿现象） |

> 说明：本分配表作为课程预置测试程序与现场验收的评分依据。
> **若教学需要调整策略分配，仅需修改本表，测试套件与接口规范保持不变。**
>
> 补充约定：
> - 基线 `kernel/course_sid.h` 中 `LAB4_POLICY_ID` 的注释（"0=MLFQ 1=彩票 2=步长 3=优先级…"）为早期占位文字，
>   与本表不符；宏的**数值**（= 学号 % 10）正确，策略含义以本表为准。
> - "tick"指一次时钟中断。若你在 lab2 中把 `LAB2_TICK` 实现为"每个时间片包含的中断次数"，
>   ID 0–2 的最高级时间片即 `LAB2_TICK` 个 tick；若实现为"时钟中断周期的倍数"，最高级时间片取 1 个 tick。
>   两种口径均可，须在设计笔记中写明所用口径；判据看档位数量与逐级 ×2 关系。
> - `setickets` 设定值覆盖 ID 3 的静态默认票数与 ID 5/7 按进程名分配的默认票数（课程测试据此设票）。
